# Security boundaries

Run Bazak on a trusted machine for one shopper. The start scripts bind both apps to `127.0.0.1`, and the Compose database port binds to loopback. Local clients that can reach the services can access the shared shopper history and evaluation evidence. Conversation IDs identify records. The apps have no login, user isolation or global inference quota. Keep the listeners private and keep `OPENAI_API_KEY` and any database credentials in the server environment or an ignored `.env`. The Compose defaults are for local development. [Local setup](../README.md#run-locally) · [Compose configuration](../compose.yaml)

## Controls and verification

- **Browser writes and loopback requests.** The documents and shopper API check the `Host` against `127.0.0.1` or `localhost` at the configured listener port. Shopper POSTs reject cross-origin browser metadata and require uncompressed UTF-8 JSON. Local command-line clients may omit browser headers. The API sends no cross-origin grants. [OpenAPI contract](../apps/web/openapi.yaml) · [HTTP tests](../apps/web/src/server/http.test.ts) · [OWASP CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)
- **Request size and error handling.** The API counts streamed bytes up to 64 KiB, allows 10 seconds to finish reading, and validates path and body schemas before initializing services. Invalid inputs and upstream failures return fixed messages. The transport logger records operation, phase, code and HTTP status when available. [Request reader](../apps/web/src/server/write-request.ts) · [HTTP tests](../apps/web/src/server/http.test.ts)
- **Model and catalog permissions.** Models propose typed operations. Application code checks text-derived keywords and resolves card and failed-group references against the last eight completed turns. A planner can suggest soft preferences from same-category search evidence, while application code enforces search constraints and chooses queries. The catalog adapter uses fixed DummyJSON routes, validates parameters, rejects redirects and stops reading a decoded response that exceeds 512 KiB. The framing stage only emits approved sentences. [Conversation tests](../packages/features/conversation/src/application/chat.test.ts) · [Planner tests](../packages/features/conversation/src/application/query-planner.test.ts) · [Catalog tests](../packages/adapters/dummyjson/src/catalog.test.ts) · [OWASP prompt injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)
- **Stored and streamed content.** React renders shopper text, product text and evaluation evidence as text. Both production apps serve an uncached, dynamically rendered document with a fresh script nonce, a content security policy and anti-framing headers. Development allows the inline styles and script evaluation needed for Next.js hot reload. Product thumbnails load directly in the browser from approved HTTPS DummyJSON CDN paths and display a fallback if unusable. [Browser policy](../apps/shared/browser-security.ts) · [Chrome tests](../tests/shopping.spec.ts) · [Next.js CSP guide](https://nextjs.org/docs/app/guides/content-security-policy)
- **SQL and turn state.** Prisma model operations handle reads and writes. The advisory locks use fixed tagged SQL with bound parameters where values are needed. Transactional checks allow one running turn per thread, and attempt numbers prevent stale results from overwriting a newer generation. [Conversation storage](../packages/adapters/evaluation-store/src/conversations.ts) · [Database test](../packages/adapters/evaluation-store/src/conversations.integration.test.ts) · [Prisma raw query guidance](https://www.prisma.io/docs/orm/v7/prisma-client/using-raw-sql/raw-queries#sql-injection-prevention)
- **Changes to these controls.** Oxlint rejects common raw HTML and evaluation sinks, unsafe Prisma calls and ordinary function-call use of tagged SQL methods. Review tagged SQL for fixed query text, and pass input as bound values. Installed Lefthook hooks run `pnpm check` before pushing. [Lint configuration](../.oxlintrc.json) · [Tagged SQL rule](../tools/oxlint/security/index.mjs) · [Hook configuration](../lefthook.yml)

Run `pnpm check` with local Docker and Google Chrome for the contract drift, lint, production build, isolated PostgreSQL and browser checks. The browser tests cover fixture streaming, recovery through reload, inert stored text in both apps and fresh document nonces. The standard check uses fixtures for shopping inference. [Verification commands](../README.md#verification-and-measured-results)

## Live data and remaining risk

- Live intent sends the current message and a bounded projection of recent conversation context to OpenAI. The optional planner sends structured same-category shopping evidence, and the framing call sends fixed sentences. The provider requests specify `store: false`. Review provider data controls before entering private material. [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data)
- DummyJSON receives the category, search terms or product ID needed for a lookup. The CDN receives the browser's image request without a page referrer. Local PostgreSQL retains conversations and evaluation evidence until its data is removed. Use the credential-free fixture for offline inference with synthetic data.
- Model decisions can still be wrong within allowed operations, including choosing an irrelevant category, proposing the wrong price filter or asking an unnecessary question. Per-attempt deadlines, call budgets, token limits and the per-thread lease limit individual work. Multiple threads can still spend provider quota or grow the database. Shared or public use would require identity, per-user authorization and resource quotas.
